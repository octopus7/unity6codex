# 파츠 보행 독립 프리뷰 평가
작성일: 2026-09-05

## 결과 판정
기술 검증 시안 구현. 최종 보행 품질은 미달.
frame_01.png를 디자인 기준으로 사용했다. 사용자 수정 지시에 따라 앞면 아틀라스를 보존하고 후면 아틀라스를 추가하여 두 면을 포즈별로 교대한다. 완성 보행 프레임은 이미지 모델로 생성하지 않았다.

## 파일과 실행
- preview.html: 더블클릭하여 브라우저에서 실행. 서버나 외부 라이브러리 불필요. preview.js와 preview_data.js를 같은 폴더에 둔다.
- 재생/정지, 4개 포즈 선택, 120샘플 슬라이더, 관절 표시, 망토 숨김, 앞면/뒷면 고정 비교, 속도 선택.
- walk_key_01.png ~ walk_key_04.png: 코드 합성 핵심 프레임.
- comparison_sheet.png: 2×2 비교 시트.
- walk_loop.gif: 48프레임 1.2초 반복 프리뷰.
- atlas_source.png / atlas_rear_source.png: 내장 image_gen 생성 원본.
- atlas_front_rgba.png / atlas_rear_rgba.png: 배경 분리한 투명 아틀라스.
- parts/front 및 parts/rear: 각 18개 PNG, 총 36개. 실제 기본 동작에서는 머리·망토·화살통·활을 앞면으로 고정하고 신체 파츠 면을 교대.
- rig.json: 원본 절단 사각형, 추가 trim 좌표, 원본 크기, 기본 그리기 크기, 피벗, 부모 연결점, 각도, 면 선택, 그리기 순서와 120샘플.
- build.py: Pillow와 NumPy로 추출/리깅/PNG/GIF/데이터 재생성. python build.py 실행.
- generation_prompt.txt: 내장 image_gen 사용 프롬프트와 투명 배경 실패 기록.
- validation.json: 수치 검사 결과.

## 직접 확인한 항목
- 4프레임 비교 시트 및 보정 후 3번 프레임을 직접 확인.
- 얼굴은 같은 오른쪽 방향 머리 이미지를 유지.
- 가까운 다리 발목 x좌표: 1번 359 → 3번 279. 가까운 손 x좌표: 286.56 → 389.04. 같은 쪽 팔과 다리가 반대로 교대.
- 가까운 허벅지 금색 장식과 먼 허벅지 단순 스트랩은 동일한 bone ID를 유지한다. 장식만 다른 다리로 옮기는 방식이 아니다.
- 120샘플에서 뼈 길이 오차 최대 약 4.3e-14px, 지지 발목 높이 오차 약 5.7e-14px, 활 부착점 오차 0px.
- 위 수치는 좌표 연결만 증명한다. 실제 손가락이 손잡이를 자연스럽게 감싸는지는 별도 시각 품질 문제다.
- 원본 이미지와 Unity 씬은 수정하지 않았다.

## 남은 문제
1. 두 구도의 몸통/골반 윤곽 차이가 크다. 현재 1/4 및 3/4주기 부근에서 면이 즉시 교체되어 튄다. 보행 회전보다 몸을 뒤집는 느낌이 날 수 있다. 중간 측면과 부위별 면 전환 시점 조절이 다음 개선 대상.
2. 머리를 오른쪽으로 고정한 상태에서 후면 몸통의 어깨 방향이 과도하게 돌아 보인다. 두 아틀라스의 카메라 각도가 충분히 정합되지 않았다.
3. 무릎의 둥근 절단 윤곽과 이중 외곽선이 보인다. 팔꿈치·어깨도 겹침과 두께 튜닝이 더 필요하다. 목 틈은 위치로 보정했으나 자연스러운 목/칼라 결합은 미완성.
4. 후면 시안은 부품 길이와 폭이 달라 동일 리그 크기로 정규화했다. 그리기 크기는 고정되지만 원화의 두께·원근과 장식 모양 차이는 남는다. 완전히 동일한 의상 원화로 볼 수 없다.
5. 활은 가까운 손 자식으로 고정되지만 스윙할 때 얼굴/몸과 겹친다. 손잡이 파지와 무기 회전 포즈를 더 조정해야 한다.
6. 생성 모델은 실제 알파 요청 및 보정 요청 모두 RGB 체크무늬를 반환했다. 외부와 연결된 밝은 무채색 배경을 추출 코드로 분리했다. 가장자리 밝은 잔색과 내부 체크무늬 잔류 가능성이 있으므로 최종 게임 자산 품질은 아니다.
7. 발은 제자리 보행 기준으로 뒤로 움직이며 지면 격자도 같은 속도로 움직인다. 지지 구간 발목 높이는 일정하다. 반면 착지/이륙 경계의 수평 속도 변화, 부츠 원화 교체에 따른 밑창 윤곽 변화는 남는다. 픽셀 단위 무미끄러짐은 입증하지 않았다.
8. pose(0)==pose(1) 수치상 동일. 하지만 GIF 마지막→첫 프레임 재생의 지각적 매끄러움은 보장하지 않으며, 면 전환과 접지 속도 불연속을 포함한다.
9. JS 구문 검사는 통과. 브라우저 보안 정책이 로컬 file URL을 차단하여 실제 브라우저에서 버튼·슬라이더·반복재생 동작은 검증하지 못했다. 이 제한을 우회하지 않았다.

## 다음 개선 우선순위
먼저 같은 카메라 범위로 앞·뒤 파츠 윤곽/연결부를 맞추고, 몸통·골반 중간 측면을 추가한다. 이어 관절 겹침 및 손잡이 파지를 다듬고 접지 속도를 연속화한다. 현재 시안으로 Unity 가져오기나 성공 판정을 진행하지 않는다.
